# 야시장 한입특급 v59 업그레이드·검증 리포트 (20260928)v1

## A. 핵심 결론
1. **v59(0.18.0) 변경 5건을 적용했고 회귀는 없습니다.** 원본 테스트는 128/128 통과했습니다(기존 121건과 새 7건). 엔진 자동 플레이는 200/200단계를 클리어했고(새치기 거절·수락 모두), 브라우저 E2E는 12/12 통과했습니다.
2. **3성 기준이 약 40% 짧아졌습니다.** 1단계는 4:30에서 2:30으로, 200단계는 4:45에서 3:00으로 줄었습니다. 전체 범위는 255~300초에서 150~180초가 됐습니다. 생각 시간 0초로 움직임이 멈출 때마다 배차하는 봇은 87.6~145.4초가 걸렸고, 200단계 모두 새 3성 안에 들어왔습니다.
3. **재방문 장치와 코인 사용처가 생겼습니다.** 출석은 1일차 20코인에서 7일차 이후 80코인까지 늘어납니다. 오늘의 미션은 매일 3개(30~80코인)입니다. 등불 테마 3종(300·600·1000코인)을 새로 판매합니다.

## B. 데이터 범위 및 정의
- **대상:** 원본 `ysmilk01-maker/pickup-rush-color-station`의 브랜치 `claude/v59-upgrade`와, 배포본 `pickup-rush-play`의 같은 이름 브랜치입니다. 비교 기준은 v58(원본 `a2aac9a`, 배포 `2940fe3`)입니다.
- **실행 환경:** Claude Code 클라우드 세션, Node v22.22.2, Playwright 1.56.1(Chromium), 390×844 모바일, 배율 2
- **지표 정의**
  - 3성 목표: `STAGE_TIMES`. 2성은 기존대로 3성의 1.5배입니다.
  - 자동 주행 시간: `AUTO_TIMES`. 정답 순서로 배차하고, 매번 움직임이 멈출 때까지 기다린 시간입니다.
  - 봇 시간: `headless-campaign.mjs`로 누적한 엔진 시간입니다.
- **범위 밖(이번에 적용하지 않음):** 추천안 2번(71단계 이후 새 장치)과 4번(러시 모드). 실제 이탈 데이터를 본 뒤에 결정하는 후속 과제로 남겼습니다.

## D. 검증 및 한계
- **데이터 품질 이슈:** 브라우저 E2E의 1단계 클릭 수가 실행마다 달랐습니다. 통합 실행 2회에서 85회와 79회가 나왔고, 최종 실행과 개별 재실행에서는 43~44회였습니다. 같은 도구로 v58을 재면 45회였습니다. 원인을 따로 확인한 결과, 거부된 클릭은 v58 4~5회, v59 4회로 같았고(사유: 승강장 가득 참), 프레임도 v58 60.3, v59 58.7로 같은 수준이었습니다. 1.3초 고정 대기 방식의 클릭 봇이 실행 시점 부하에 따라 흔들리는 것이라 v59 결함은 아니라고 판단했습니다.
- **계산상 가정:** 3성 목표는 설계값입니다. 실제 이용자의 플레이 시간 표본은 1단계 자동 클릭 1회뿐입니다. 새 기준이 사람에게 너무 어려운지는 실제 플레이 기록으로 다시 보정해야 합니다.
- **기존 기록:** 별은 최고 기록을 유지하므로(`Math.max`) 이미 받은 별은 줄지 않습니다.
- **오늘의 미션:** 하루의 기준값은 그날 첫 접속 시점의 누적 기록입니다. 기기 시계를 바꾸면 날짜가 바뀔 수 있습니다. 로컬 저장 게임의 구조적 한계입니다.
- **해석의 한계:** 재방문 효과와 재미는 가설이며 측정하지 않았습니다.
- **추가 확인 필요:** 실기기에서 확대된 승객의 가독성, 새 테마의 색감, Android 빌드(0.17.2 심사 중)에 이번 변경을 넣을 시점.

## E. 재현 가능한 계산 근거
```bash
# 원본 저장소
npm run campaign:times      # 3성 목표 재계산 (dist/stage-times.js 생성)
npm run check && npm test   # 구문 검사, 128개 테스트
# 배포 저장소
bash tools/verify/run-all.sh "reports/v59검증(20260928)v1"
```
- **3성 공식:** `three = ceil((AUTO_TIMES[i] + 차량수 × (1 − i/400) + 15) / 15) × 15`, `two = ceil(three × 1.5)`
- **출석 보상:** `20 + 10 × min(6, 연속일수 − 1)`
- **오늘의 미션:** 세 묶음(완료 횟수, 탑승 인원, 3성 완료)에서 날짜 번호에 따라 쉬운 것과 어려운 것을 번갈아 1개씩 고릅니다.
- **원본 결과:** `static-check.json`, `campaign-decline.json`, `campaign-accept.json`, `e2e/browser-e2e.json`, `ui/`
